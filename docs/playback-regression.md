# 播放链路回归与基线测试（阶段 0）

基线：iahc-1.2.10。对照版本：iahc-1.2.11（异步 Bridge + 媒体状态恢复）。

## 采集方式

- 启用应用调试日志并导出日志；查询 `playback.perf` 和 `bridge`。
- 网页端 `window.__splPerfEvents` 是最多 80 条事件的环形缓存，仅包含事件类型、耗时和时间戳。
- 采集：歌曲行点击（play-click）、歌曲状态变更（play-state）、浏览器长任务（long-task，>=50ms）、事件循环延迟（event-loop-lag）、原生请求耗时（native-fetch）以及播放器初始化结果。
- 禁止记录 Authorization、Cookie、完整 URL、歌曲名称或任何认证令牌。

## 必须验证

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 首次启动 | 登录后播放列表第一首 | 底部播放器出现；通知栏展示正确歌曲；可滚动 |
| 连续切歌 | 连续点击 5 首不同歌曲 | 最后一首生效，无重复暂停或错误跳歌 |
| 长时间闲置 | 后台 10～30 分钟再播放列表歌曲 | 页面可操作；播放器和通知同步刷新 |
| 缓慢网络 | 模拟弱网或关闭网络后点播放 | 页面仍可滚动，有限时失败提示，无长期卡死 |
| 网易云歌词 | 切歌后歌词首次加载 | 歌词查询不阻塞点击；旧结果不覆盖新歌曲 |
| SpicyLyrics | 无官方歌词的歌曲 | 查询异步，不阻塞官方歌曲元数据 |
| 下载 | 下载歌曲及集合 | 下载不受 Bridge 更改影响 |
| Spotify Connect | 本机与远端设备切换 | 操作不错误路由，通知栏仍更新 |
| 后台控制 | 通知栏播放、暂停、切歌 | 状态与页面一致 |
| 播放器模式 | 原始、迷你、全屏之间切换 | 自定义播放器与原生播放器至少一个保持可用 |
| 页面导航 | 请求进行中重新加载登录页面 | 上一页回调丢弃，无 JS 崩溃 |
| 二进制响应 | 字节 00 FF 01 通过原生 Bridge | `arrayBuffer` 保留原始字节 |

## 定量记录（不要预填“通过”）

每次测试记录设备型号、Android WebView 版本、网络环境、播放器模式、是否开启省电、是否开启隐藏空播放器，以及：

- 点击歌曲到状态更新（ms），至少 10 次：P50 / P95。
- 单次点击后的最大 Long Task 和事件循环延迟（ms）。
- 长时间闲置后首次播放成功次数 / 尝试次数。
- 底部播放器出现率及通知栏元数据更新率。
- 出现失败时，保存诊断日志的事件时间戳与对应步骤。

## 自动化

运行 `node --test tests/bridge-contract.test.cjs` 验证 Native Fetch Promise、状态码、Response.clone、二进制响应和取消；CI 使用 Android Release 构建确保 Kotlin / Gradle 编译通过。

注意：自动化不等于真实 Spotify WebView 测试；最终兼容性仍需真机验收。
